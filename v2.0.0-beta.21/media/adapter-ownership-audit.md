# Adapter refactor: ownership and failure audit

This audit covers the issues raised during the Swift, Kotlin, and TypeScript refactors, and a fresh source/probe audit of the revised TypeScript implementation. Swift/Kotlin entries below capture the prior reviews' lessons; they are not a new certification of those worktrees. TypeScript baseline comparisons use this worktree's Git HEAD, before its uncommitted refactor.

## What went wrong

Both pre-existing defects and refactor regressions were involved. The TypeScript HEAD already had independent overlapping refreshes, a single pending SSE resolver, and a truthiness check that discarded valid falsy events. The response-body error-class heuristic and loss of BYOB support were introduced by this refactor. Upload source-error preservation and prompt cancellation during adapter body reads were gaps in implementing the new cancellation contract.

Passing examples did not establish the contract. Previous tests covered a marker escaping an adapter, but not an adapter handling a failed body and deliberately throwing a different native abort. They covered streamed payloads, but not the byte-stream reader API. The next iteration tested enqueue-based byte producers but missed producers that require a BYOB view; decoded empty strings but not empty wire data; and omitted versus replaced request bodies but not native null-body inheritance. The revised tests vary ownership, consumer, failure origin, and termination separately.

The repeated escapes were also a review failure: some fixes established an invariant in one helper without checking every caller that could bypass it. Removing the source-error heuristic left cause traversal around whole operations. Correct iterator termination left the parser dispatching the remainder of a chunk. Correct stream ownership left one event-source request copy outside the copy helper. Counting passing tests did not establish that these invariants held across those boundaries.

## TypeScript boundary simplification

`src/util/owned-body.ts` is the one owner for application-created streams. It owns a reader, records source failures, releases abort listeners and locks, and preserves byte-stream capability. It does not tee, buffer the whole body, or read ahead on behalf of a consumer. Native Response methods still perform bulk collection.

Native Fetch responses are left intact when adapters observe or copy their headers. Only independent replacement bodies need a new source owner. Known transfers through native constructors retain resource identity, including Bun's constructor behavior where the returned stream handle can change. We do not infer ownership from matching URLs, headers, or error classes.

Native read/fetch error repair is narrowly scoped. Managed body instances receive small wrappers around their native bulk-read methods; custom method overrides are preserved. Those wrappers end before control returns to an adapter or decoder. `nativeBodyOperation` likewise surrounds only Fetch itself. The old response error WeakMap heuristic is removed. Native cause traversal now lives only inside `nativeFetch`, shared by managed execution and the default standalone event source. `requestFailure` only selects an explicitly aborted signal's reason; it no longer traverses application causes in adapters, decoding, validation, or SSE policy. The source owner surrounds native Fetch repair, so a known original source error takes precedence even when it has a nested stop cause.

Uploads use the same owner through `prepareRequestBody`; unsupported engines still use the bounded Blob fallback. Request body reads acquire ownership lazily when needed, so unread native Blob/string requests retain replayable native sources. `copyRequest`/`copyResponse` preserve known body ownership through their constructors. Adapters creating streams should use the shared preparation/copy helpers; arbitrary platform constructors and direct Fetch calls outside Sunday retain their platform semantics.

Source errors, caller aborts, and consumer cleanup are distinct. In particular, Fetch cancelling an upload during a network failure must not overwrite the native network error with a cleanup reason. An adapter's explicit Error, TypeError, AbortError, branded stop, or falsy rejection is never rewritten based on the history of its input body.

## Additional issues found by applying the rules

- Late resource cleanup discarded the original cancellation reason: fixed in the shared abort helper.
- A request adapter could begin a native body read and throw without awaiting it: source ownership now allows cleanup of that locked reader too.
- Parameter validation wrapped stop/abort errors: those now propagate unchanged; ordinary validation failures retain RequestValidationError.
- A GET/HEAD upload could allocate or buffer a producer before native request construction rejected it: method/body validation now precedes factory invocation, and request preparation disposes created streams on failure.
- SSE discarded valid `0`, `false`, and `""`: it now skips only decoded `undefined`. Empty wire data also reaches the decoder; control frames without data do not.
- Consumer cancellation during a failed Fetch could be mistaken for a source failure in the new shared owner: source failure, explicit stop, and consumer cleanup now use distinct paths.

## Native limits verified during the latest regression pass

Bun 1.3.10 leaves an outstanding BYOB read pending after native reader cancellation and refuses to release that reader's lock. Its BYOB reader also stalls on a partial write smaller than a multi-byte element. The tests compare cancellation capability with a native reader and use supported byte-sized partial reads and aligned typed reads. Sunday explicit abort still errors its output immediately with the original reason, cancels the source, and removes listeners; native lock-release failure cannot replace that result. Direct consumer cancellation retains the engine's behavior. No source buffering or BYOB downgrading is introduced to conceal these limitations.

Firefox does not expose Request.body in the tested version. Same-URL copies retain native hidden-source inheritance, and unsupported application uploads use the existing buffering fallback. A synchronous URL-changing copy cannot transfer an inaccessible native body; the copy matrix tests explicit replacements there and inheritance where Request.body is available.

Byte-stream forwarding follows [native auto-allocation](https://developer.mozilla.org/en-US/docs/Web/API/ReadableStream/ReadableStream) and [returning transferred BYOB views](https://developer.mozilla.org/en-US/docs/Web/API/ReadableStreamBYOBRequest/respondWithNewView). The owner retains one reader instead of probing with a disposable reader, and uses the same native bulk consumers as before.

## SSE framing correction

The next review reproduced two pre-existing framing errors against native EventSource: legal LF+CR/CRLF endings merged events, and stripping delimiters before streaming UTF-8 decoding let an incomplete character corrupt the following field name. The former byte-pattern scanner was not a complete implementation of line endings; decoder streaming state was applied to event fragments rather than the actual byte stream.

`EventParser` now sends the original bytes directly through a native streaming TextDecoder, then recognizes CR, LF, and CRLF lines. It retains fragments of only the unfinished text line and the current event's lines. Each fragment is joined once when its line completes, and data fields are joined once when the event completes. Raw-byte buffer concatenation, separator scanning, and the caller's per-chunk byte copy are removed. Parser state remains connection-local; EOF does not manufacture a delimiter or dispatch an incomplete event.

Bun 1.3.10 does not remove a leading BOM when its UTF-8 bytes span decoder calls. The parser uses native decoding with `ignoreBOM: true` and removes exactly one leading decoded BOM itself, consistently on every runtime. An interior or second BOM remains data. Cancellation discards text fragments and any pending decoder bytes; callback/source errors retain their original identity. No custom UTF-8 decoder or replacement stream layer was added.

The shared `sse-framing-checks.mjs` matrix covers all CR/LF/CRLF pairs (including CR+LF forming just one line ending), every two-chunk byte split, one-byte chunks, empty chunks, offset typed-array/DataView inputs, multi-byte Unicode, BOM boundaries, malformed and truncated UTF-8, long lines, multiline data, comment heartbeats, and control-only frames. Real HTTP/1 and HTTPS/HTTP2 peers send both complete and byte-sized writes. Chromium, Firefox, and WebKit additionally compare Sunday messages with their native EventSource using the same peer and fixtures; Node and Bun run the same parser and transport contracts. The existing reconnect, native-stream/BYOB, cancellation, and error-provenance suites remain in the full check.

References: [streaming TextDecoder](https://developer.mozilla.org/en-US/docs/Web/API/TextDecoder/decode), [SSE interpretation and line endings](https://html.spec.whatwg.org/multipage/server-sent-events.html#event-stream-interpretation).

## SSE lifecycle and field-validation follow-up

The byte framing repair did not fix surrounding, pre-existing lifecycle paths. A timeout notification could close or abort a subscription and then schedule a new connection; raw Unicode IDs threw during reconnect setup; iterator failures lost their reason during upstream close; OAuth cleanup was still awaited; and reducing fields to a dictionary before validation discarded earlier valid IDs/retry values. Empty event types also retained an empty string instead of the default message type.

The revised implementation uses one guarded reconnect transition for timeout, network error, and EOF. It checks the connection identity after notifications, detaches connection resources before invoking cancellation callbacks, and protects successor listeners/timers from old cleanup. Request/header construction runs inside the observed async error boundary. Last-Event-ID uses UTF-8 bytes encoded into the Fetch header's ByteString. Iterator termination now sets state once, closes upstream with the same reason, and settles all pending readers; falsy errors remain failures. OAuth transient and rejected-discovery responses use the existing nonblocking discard helper, so cleanup cannot delay or replace the intended provider failure.

The parser processes each completed line immediately. It retains current event fields and data fragments, not all raw lines. Comments and unknown fields are discarded; valid id/retry fields survive subsequent invalid fields. Empty event types are normalized at dispatch. Native streaming decoding, body ownership, bulk readers, BYOB support, and native upload behavior are unchanged.

Shared regressions cover timeout/network notifications that close, abort, or replace the source; cancellation callbacks that start successors; real HTTP/1 and HTTP/2 UTF-8 reconnection headers; synchronous request construction failures; decoder/iterator failures with concurrent pending readers; exact producer/signal error identity; and resolving, rejecting, and never-settling cleanup. OAuth acquisition, refresh, and discovery paths include transient status classes and rejected discovery responses. Field fixtures run at every byte split and compare native browser payloads and IDs.

Two native differences were verified rather than hidden with transport shims:

- Bun 1.3.10 double-encodes header bytes on the wire. An independent Node peer confirmed this, and Bun 1.4.4 passes the same regression. Bun execution now requires >=1.4.0; development and CI pin 1.4.4. See [Bun's header encoding fix](https://github.com/oven-sh/bun/pull/35338).
- Firefox's native EventSource drops an ID supplied in a control-only frame. Sunday retains that ID as required by the [SSE dispatch algorithm](https://html.spec.whatwg.org/multipage/server-sent-events.html#event-stream-interpretation). This fixture asserts Sunday's ID against an explicit expected value and compares native payloads; fixtures with IDs on data events also compare native IDs in all three browsers.

Temporary mutation builds restored the reviewed failure paths independently. The unchanged shared tests rejected unguarded timeout reconnection, raw Unicode headers, lost upstream reasons, awaited OAuth disposal, invalid ID overwrite, invalid retry overwrite, and empty event-type dispatch. The current build passed the same tests. Mutations and their output stayed outside the worktree.

## Credential cancellation and filtered-response follow-up

The next review identified two pre-existing boundary defects: query-credential redaction reconstructed status-zero responses before adapters could inspect them, and cancelled token acquisition retained the per-key lock until an uncooperative provider settled.

Redaction now preserves the native filtered response and changes only its exposed URL metadata. It neither reconstructs the response nor clones or tees the hidden body. Responses whose URL needs no redaction are returned directly. Real manual redirects cover header and query credentials in buffered and event-stream execution, including response adapters that return replacements or throw the original stop error.

TokenManager now uses the existing abort helper around provider acquisition and refresh only. Last-waiter cancellation releases the provider wait and the lock; a successor does not depend on abandoned work settling. Late fulfillment and rejection remain observed, but cannot reach persistence. Storage mutations remain serialized: abandoning a pending removal could erase a successor's token, and abandoning a refresh commit could lose a rotated refresh token. Cancellation during invalid-grant removal also prevents the cancelled operation from starting a fallback acquisition afterward.

`credential-boundary-checks.mjs` runs inside the lifecycle suite's unhandled-rejection monitor in Chromium, Firefox, WebKit, Node, and Bun. It covers export, buffered, and streaming acquisition/refresh; marker, ordinary Error, and null cancellation reasons; and abandoned provider promises that resolve, reject, or remain pending. It asserts successor completion before old-provider settlement, exact cancellation identity, no stale cache write, pending-removal serialization, and retained refresh commits.

Same-URL request copying now uses the native Request constructor on every supported runtime. The old Bun explicit-stream transfer workaround is removed; real-socket upload, cancellation, and body-ownership tests exercise native inheritance. URL-changing copies retain their existing transfer path.

The proposed removal of the leading-BOM guard was rejected by the complete framing matrix. Node v25.8.1 strips both consecutive leading BOMs when the first spans decoder chunks; the earlier single-BOM probe missed this. The small guard therefore remains, with native streaming decoding and `ignoreBOM: true`, to remove exactly one leading BOM without altering malformed UTF-8 handling. The Bun 1.3.10 observations above describe historical evidence, not the current supported minimum of Bun 1.4.0.

## SSE activity, control, and notification boundaries

Four further pre-existing failures shared a gap in the old tests: they used complete heartbeat frames, handler properties instead of EventTarget error listeners, and valid numeric delays without testing the timer's range. The tests passed while healthy incomplete messages timed out, retry lines at EOF were discarded, large delays overflowed into immediate reconnects, and registered error listeners never heard terminal failures.

Activity now means a nonempty byte read. The parser does not generate empty heartbeat records or track `hasLines`; it discards comments and unknown fields. Message data and reconnect IDs still take effect at a blank line. The parser constructor's separate `EventControl` callback receives completed retry/keepalive/retry-max lines immediately; `EventInfo` now contains only message fields. EOF still discards incomplete messages and incomplete control lines. Cancellation is checked after either callback, before any remaining lines or bytes can be processed.

Reconnect delays are capped at the native signed-32-bit timer maximum, for both the first attempt and exponential backoff. The wire retry value remains available through `retryTime`. A zero retry remains zero even after enough failures to overflow exponentiation. Timer polling is bounded too. One notification helper now invokes the handler property with the event-source receiver and dispatches the same event through EventTarget for open, message, and error; native once/removal semantics are retained.

The new `sse-control-checks.mjs` runs inside the shared lifecycle suite in Chromium, Firefox, WebKit, Node, and Bun. It covers real HTTP/1 and HTTP/2 heartbeat and partial-message streams, retry lines followed immediately by EOF, empty chunks, native timer overflow, stepped long backoff timers, error listeners stopping reconnects, handler/listener event identity, and buffered/streaming adapter stop identity. The framing matrix checks controls separately at every byte split and preserves callback error/cancellation identity. Existing byte-stream ownership, native upload, UTF-8, refresh commit, and cancellation suites remain required. No new stream wrapper or collection strategy is introduced.

Validation passed with 947 tests, lint, typecheck, build, and the shared browser/Node/Bun suites. Minimum-supported Bun 1.4.0 also passed. Temporary mutation builds independently restored missing byte activity, overflowing timers, retry staging until a blank line, and omitted error dispatch; the unchanged control suite rejected all four and passed the current build. Mutation artifacts remained outside the worktree.

## Raw request entry and observer isolation

The next review found an ownership gap introduced by the refactor: pre-aborted native Requests failed before `sent` was assigned, so cleanup had no body to discard. The request execution now starts with the input as its cleanup target and replaces it as ownership transfers. Error disposal uses that target unconditionally and remains nonblocking; no body wrapper, clone, or early read was added.

The observer failure was pre-existing. Direct calls to handler properties entered the connection's failure chain: a thrown message observer triggered retries and duplicate delivery, while a thrown error observer stranded the connection and suppressed registered error listeners. Properties now participate in native EventTarget dispatch using a temporary listener for the same event. Existing listeners run first; stopImmediatePropagation may skip the property. The listener matches event identity to tolerate recursive dispatch and is always removed after dispatch. Handler results are returned to EventTarget so rejected promises retain native reporting too. Named SSE delivery to onmessage is preserved. Adapter/decoder failures remain request outcomes; observer failures are notifications reported by the runtime.

The shared notification matrix checks property/listener registration, open/message/error notifications, synchronous throws and rejected promises, ordinary/stop/abort error identity, successful streaming after observer errors, legitimate network reconnection, terminal adapter failures, named events, recursive dispatch, cleared handlers, and stopped propagation. It captures intentional native exception/rejection reports separately from the existing no-unhandled-rejections lifecycle matrix. Raw-request coverage checks pre-aborted requests with cleanup that resolves, throws, rejects, or remains pending. It uses native streams where supported and buffered native requests on engines without stream uploads; the existing streaming and cancellation matrices remain in every full check.

Validation: the full check passed 948 tests plus lint, typecheck, build, browser checks, and Node/Bun shared suites. Package import checks and the minimum-supported Bun 1.4.0 matrix also passed. The notification suite waits for native error/rejection reporting rather than assuming a single timer tick, which Firefox does not guarantee. Temporary mutation builds restored missing raw-input cleanup and direct property invocation independently; the unchanged regression suites passed the current implementation and rejected both variants. Mutation artifacts remained outside the worktree. Documentation validation retains the existing missing Schema Runtime Guide link warning.

## Header validation and native request branches

The remaining cleanup failures exposed two gaps in transfer coverage: validation after ownership transfer and a native constructor that changes the source handle. Header adapters now build and validate Headers before copying the request, so invalid names or values leave the input body untouched.

Bun's native Request constructor can tee an upload and replace the input request's body with one branch. Retaining only the pre-construction source does not suffice: that source is locked by the tee, and cancelling only the returned branch cannot stop the producer. `copyRequest` identifies the post-construction input handle when it changes. The initial fix retained these native branches for failure cleanup; the branch-lifetime correction below replaces that tracking with immediate disposal. Managed bodies continue to stop through their source owner. No additional stream wrapper, tee, eager read, or buffering is introduced; native body replayability and BYOB behavior remain covered.

Caller-visible failures keep their exact identity, including when cleanup throws, rejects, or never settles. Managed source cancellation also retains exact identity. Raw source callbacks retain native forwarding semantics: Chromium may omit the reason, while Bun may supply nested tee cancellation arrays. The shared tests measure native forwarding separately instead of promising semantics that native Request copies do not provide.

Regression coverage uses raw native bodies and helper-managed bodies at direct adapter, buffered execution, and streaming execution boundaries. It exercises repeated transfers, invalid header names/values, stop errors, caller abort, and all cleanup outcomes. Firefox exercises raw Blob bodies and the managed buffering fallback because native upload streams are unsupported. Focused static/refreshing token-adapter tests additionally prove that invalid headers leave the input body readable and unchanged. This matrix supplements successful native uploads, redirects, byte streams, and bulk-reader coverage.

Validation passed with 952 tests, lint, typecheck, build, Chromium/Firefox/WebKit regressions, and the Node/Bun shared suites (649 ownership checks per native runtime). Minimum-supported Bun 1.4.0, package imports, and all seven release-helper tests passed too. Temporary mutation builds restored late header validation and omitted native branch retention independently; the shared regressions rejected both. Documentation validation retains the existing missing Schema Runtime Guide link warning.

## Retire obsolete branches during ownership transfer

Failure-only cleanup missed successful uploads: Bun retained the complete upload in its unused native tee branch. Lazy ownership installed by a bulk read also replaced the old metadata, losing those retained branches before a later stop. These were two consequences of allowing an obsolete branch to outlive its transfer.

`inheritBody` now cancels the changed input handle immediately, without awaiting native cancellation. It checks that the handle differs from both the pre-copy source and the returned body; engines may transfer or share the active handle instead of creating a separate branch. The branch set and deferred traversal are removed. One small stream-cancellation helper serves transfer and failure cleanup. Source ownership, native Request construction, bulk collection, BYOB readers, replayable native bodies, and error propagation remain unchanged. Raw cancellation callbacks follow native forwarding, including Bun's tee arrays containing the obsolete branch's undefined reason; caller/read failures and managed source cancellation retain exact identity.

The shared ownership matrix sends successful 8 MiB raw/managed uploads through repeated copies to independent HTTP/1 and HTTP/2 peers. It checks obsolete handles at transfer time and after success, complete delivery, and absence of premature source cancellation. New read-then-stop/read-then-abort cases run at direct chain, buffered transport, and streaming transport boundaries, with throwing, rejecting, and never-settling cleanup. Firefox uses raw Blob bodies and managed buffering fallback because it cannot represent native streaming uploads. A focused unit regression checks active-body readability and retirement of the obsolete native branch.

Validation: the complete check passed 953 tests plus lint, typecheck, build, Chromium/Firefox/WebKit regressions, and Node/Bun smoke suites. The shared ownership matrix passed 907 checks in Node and 903 in Bun 1.4.4 and minimum-supported Bun 1.4.0; the count differs where native handles are shared rather than transferred. Package imports and all seven release-helper tests passed. Temporary mutation builds restoring deferred branch retention independently failed the successful-retention and read-then-stop regressions. An initial WebKit ownership run timed out; the isolated complete ownership matrix and subsequent serial full run passed. Documentation validation retains the existing missing Schema Runtime Guide link warning.
